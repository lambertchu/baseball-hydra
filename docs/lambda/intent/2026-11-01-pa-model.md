# Intent: Learned PA projection

Confirmed by owner: 2026-11-01
Mode: supervised

- **Goal:** Replace Marcel PA with an in-house PA model learned from FanGraphs batting history, so Hydra's counting stats stop over-projecting playing time.
- **Users:** The owner, when generating preseason projections and when running the public benchmark.
- **Success looks like:** Pooled 2022-2026 walk-forward PA RMSE is 165 or lower (Marcel: 190), with mean bias within ±25 PA. Hydra's 2026 counting-stat skill on all projected players is 17% or higher (Marcel: 10.9%, Steamer: 19.7%). A new all-players benchmark view shows the learned PA beating Marcel. `uv run pytest tests/` passes.
- **Non-goals:** No change to the rate models (OBP, SLG, per-PA rates) or the ROS pipeline. No public projections in the pipeline. No regeneration of `projections_mtl_2026.csv`. No 2027 data refresh. No new tests or docs.
- **Design direction:** Fit the PA model at runtime on `data/raw/batting_{year}.parquet`, which lists every hitter, so a player absent the next year counts as 0 PA. Features: PA for the last three seasons, age, age², WAR, wRC+, and games. Scale 2020 values to a 162-game pace, and never use 2020 as a label year. For benchmark year T, train only on labels through T−1. Choose linear regression or gradient boosting by a 2022-2026 backtest scored in counting stats; a tie goes to linear regression. Keep Marcel as a config fallback. Settings live in `configs/data.yaml`. Add an all-players view to `benchmark_vs_public.py` (players with 300+ PA the prior year; missed time counts as 0), and keep the 200+ PA view.

## Decisions

- Which PA source? → In-house learned model. Public projections stay comparison-only.
- Fix the benchmark too? → Yes. Add an all-players view and keep the 200+ PA view.
- Where do PRs start? → New PRs off the latest main.
